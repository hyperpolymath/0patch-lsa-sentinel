== What we do NOT claim

* *Field validation is partial, not total.* On 2026-07-02 the collectors were
  exercised against a real Windows host (LSA Protection ON, live 0patch agent
  installed) via WSL interop — see link:docs/FIELD-VALIDATION.adoc[`docs/FIELD-VALIDATION.adoc`].
  What that session established and what it did not:
** *Validated:* the registry collector — live `reg.exe` output for
   `RunAsPPL=0x1` parsed correctly as `On`.
** *Confirmed:* the 0patch install paths (`C:\Program Files
   (x86)\0patch\Agent\`, casing corrected) and the real patch-status source —
   the UTF-16LE agent log `C:\ProgramData\0patch\Logs\0patch.log`. The former
   `0patchConsole.exe list-patches` collector was a guess and has been
   removed; `opatch.rs` was rewritten against the field-confirmed log format.
** *Right-censored on protected hosts (fails closed, not `BLOCKED-INERT`, without prior log line):*
   Because `0patch.log` records *applied* patches, a host where `RunAsPPL=On`
   has always been active blocks `0patchLoader` before any `lsass.exe` patch
   can apply and be logged. Without a historical `lsass.exe` line in the 2 MiB
   tail window or a separate unblocked local catalog query, the collector can
   only report `Unknown` → `INDETERMINATE` (exit `1`, Warning `1002`), not
   distinguish `BLOCKED-INERT` from `MOOT`.
** *NOT yet observed live:* the `Present` path of the patch-status collector
   — no `lsass.exe`-targeted patch was outstanding on the validation host, so
   "`Patch NNNN applied in application lsass.exe`" has never been seen in a
   real log; and when `loader == Loaded`, `Loaded` is inferred from
   `RunAsPPL=Off` plus absence of recent block events rather than direct
   module inspection inside `lsass.exe`.
** *NOT yet observed live:* the CodeIntegrity `3033`/`3063` block-event path —
   the `wevtutil` query ran, but no 0patch block event existed on the host, so
   the positive-match branch of the event-log collector is unverified live.
* *No end-to-end scheduled-task run exists yet.* `installer/Install-LsaSentinel.ps1`
  is implemented and packaged in `release.yml`, and the Windows collectors
  type-check/lint on `x86_64-pc-windows-gnu` in CI, but the full installed
  Scheduled Task → Application Event Log (`1000`/`1001`/`1002`) cycle has not
  yet been executed end to end on a Windows host.
* *Layer A fleet policy automation is specified, not deployed.* See
  link:DESIGN.adoc[`DESIGN.adoc`] §3.1.
* *No affiliation with ACROS Security / 0patch.* This is independent,
  good-faith analysis.
