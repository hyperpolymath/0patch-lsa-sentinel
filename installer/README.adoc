== Installing lsa-sentinel (Windows)

____
The sentinel turns 0patch’s _silent_ lsass coverage loss into a loud,
un-silenceable signal. It runs as a SYSTEM scheduled task and writes its
verdict to the *Application event log* every interval. The dangerous
state (`+BLOCKED-INERT+`) is an *Error* event — pick it up in Event
Viewer or your SIEM. There is no "`don’t show again`".
____

=== Get the binary

`+lsa-sentinel.exe+` is built and published by CI on tagged releases
(see the repo’s *Releases* page). It is *not* built on non-Windows
machines. To build it yourself on Windows: `+cargo build --release+` in
`+host-rust/+`.

=== Install (elevated PowerShell)

[source,powershell]
----
# in the extracted release folder (Install-LsaSentinel.ps1 next to lsa-sentinel.exe)
.\Install-LsaSentinel.ps1                       # default: hourly
.\Install-LsaSentinel.ps1 -IntervalMinutes 15   # more frequent
----

=== What you’ll see

[width="100%",cols="14%,19%,67%",options="header",]
|===
|Exit |Verdict |Event (source `+lsa-sentinel+`)
|2 |`+BLOCKED-INERT+` — lsass patches exist but the loader is blocked
|*Error*, id 1001

|1 |`+INDETERMINATE+` — investigate |Warning, id 1002

|0 |`+OPEN-COVERED+` / `+MOOT+` |Information, id 1000
|===

A rolling log is also written to
`+%ProgramData%\lsa-sentinel\sentinel.log+`.

=== Try it without installing

[source,powershell]
----
lsa-sentinel.exe                 # live collection (needs SYSTEM for full signal)
lsa-sentinel.exe --snapshot host.snap   # classify from a key=value file (any user)
lsa-sentinel.exe --json          # stable machine line
----

=== Uninstall

[source,powershell]
----
.\Uninstall-LsaSentinel.ps1
----

=== ⚠️ Status note

The classifier core (`+core-spark/+`, `+abi-idris2/+`, `+ffi-zig/+`,
`+host-rust/+`) is formally verified and unit-tested, and the live
`+reg.exe+` (`+RunAsPPL+`) and UTF-16LE `+0patch.log+` formats were
confirmed on a real Windows host (`+2026-07-02+` — see
link:../docs/FIELD-VALIDATION.adoc[`+docs/FIELD-VALIDATION.adoc+`]).
When LSA Protection blocks `+0patchLoader+` and no prior `+lsass.exe+`
application line appears in `+0patch.log+`, the collector fails safe to
`+INDETERMINATE+` (Warning `1002`, exit `1`) rather than a false
`+MOOT+` all-clear. A live `+BLOCKED-INERT+` trigger against an active
lsass-targeted micropatch has not yet been demonstrated end to end; see
link:../AFFIRMATION.adoc[`+AFFIRMATION.adoc+`].
